# フィードバック受付サーバー（Google Apps Script）

ゲームの「設定 › フィードバックを送る」から届いた内容を受け取り、Gemini で重要度を判定して、重要度に合わせたタイミングでメールで知らせます。すべての内容は Google スプレッドシートに記録されます。

| 重要度 | 例 | メール |
| --- | --- | --- |
| 緊急 | 起動しない・落ちる・データが消えた・セキュリティ | **すぐ**（1日10通まで。超えたぶんは翌朝のまとめへ） |
| 高 | よく起きるバグ、操作できない画面、強い不満 | **毎朝8時**のまとめ |
| 中 | 小さなバグ、使いにくさ、バランス・新機能の要望 | **毎週月曜8時**のまとめ |
| 低 | 感想・応援・質問 | 毎週月曜のまとめの最後に一覧 |
| スパム | 宣伝・意味のない文字列 | 送らない（記録だけ） |

- Gemini の API キーは **このサーバー（スクリプト プロパティ）にだけ** 置きます。アプリやリポジトリには入れません（アプリに入れると誰でも取り出せてしまうため）。
- Gemini が混んでいるときや1日の上限に達したときは、いったん「判定待ち」で記録し、5分ごとにやり直します。上限に達した日はキーワードで判定するので、緊急のものはそのまますぐ届きます。
- いたずら対策: 1台につき1時間5件、全体で1日300件まで。本文は2,000文字まで。

## セットアップ（10分ほど）

1. [script.google.com](https://script.google.com/) で「新しいプロジェクト」を作り、名前を「エコーラン フィードバック」にする。
2. エディタの `コード.gs` の中身を消して、このフォルダの `Code.gs` を貼り付けて保存する。
3. 左の **プロジェクトの設定（歯車）** で「`appsscript.json` マニフェスト ファイルをエディタで表示する」をオンにし、エディタに出た `appsscript.json` をこのフォルダのものに置き換えて保存する（タイムゾーンが日本時間になる）。
4. 同じ **プロジェクトの設定** の下の **スクリプト プロパティ** に追加する：

   | プロパティ | 値 |
   | --- | --- |
   | `GEMINI_API_KEY` | Gemini API のキー |
   | `NOTIFY_EMAIL` | 通知を受け取るメールアドレス |
   | `GEMINI_MODEL` | （任意）入れなくてよい。空のままだと `gemini-flash-latest`（いつも最新の Flash モデル）を使う |

5. エディタ上部の関数選択で **`setup`** を選んで「実行」。初回は権限の確認が出るので許可する（「このアプリは Google で確認されていません」と出たら「詳細 › 安全ではないページに移動」）。
   - 記録用のスプレッドシート「エコーラン フィードバック」が Google ドライブにでき、セットアップ完了のメールが届く。
   - 毎朝・毎週のまとめメールと、5分ごとのやり直しのトリガーが登録される。
6. 右上の **デプロイ › 新しいデプロイ** → 種類「ウェブアプリ」→ 実行ユーザー「自分」、アクセスできるユーザー「全員」→ デプロイ。表示された **ウェブアプリの URL**（`https://script.google.com/macros/s/…/exec`）をコピーする。
7. その URL をゲームに設定する：`index.html` の `const FEEDBACK_URL = '';` の `''` の中に URL を入れる。設定するまで、ゲームにフィードバックの項目は表示されない。

動作確認: エディタで `testClassify` を実行すると、3つの例文の判定結果がログに出ます（記録やメールはされない）。

### コードを更新したとき

**デプロイ › デプロイを管理 › 編集（鉛筆）› バージョン「新バージョン」› デプロイ**。URL は変わりません（「新しいデプロイ」にすると URL が変わるので注意）。

## Gemini の利用枠について

- モデルは `gemini-flash-latest` のままにしておくと、新しいモデルが出たとき自動で切り替わる（古いモデルほど利用枠が厳しくなるため）。
- それでも無料枠は1日に使える回数が少ない（2026年10月時点の最新 `gemini-3.8-flash` で1日20回）。超えた日はキーワード判定になる（届かなくなることはない）。
- Google AI Studio で **課金を有効** にすると上限が大きく上がる。フィードバックの判定は1件あたりごくわずかな料金。
- 無料枠では、送った内容が Google のサービス改善に使われることがある。プレイヤーの文章を扱うので、公開後は課金を有効にした（有料枠の）キーをおすすめ。
- キーは Google Cloud コンソールで「Generative Language API だけに使える」ように制限しておくと安心。キーを誰かに見せてしまったときは作り直す。

## 記録されるもの

受信日時、ID、重要度、カテゴリ、要約、判定理由、本文、返信先メール（プレイヤーが書いた場合のみ）、アプリの種類と版、端末情報（プレイヤーが「端末情報を送る」をオンにした場合のみ：ブラウザ情報・画面サイズ・言語・レベル・最高ループ数・プレイ回数）、通知の状態。

プレイヤーから削除の依頼があったら、ID か返信先メールで探して、スプレッドシートの行を消してください。
